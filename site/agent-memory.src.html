02Definitions

Three different things get called “memory”

Most confused setups come from mixing these up. They have different inputs, different authors and different lifetimes.

Context windowRetrieval over documentsPersistent memory
HoldsThis conversation, right nowYour files, indexedFacts distilled from past conversations
Written byThe runtime, every turnYou, when you write notesThe agent, after turns
Answers“What did we just say?”“What do my notes say about X?”“What does this person prefer? What did we decide?”
LifetimeUntil the window fills or the session endsAs long as the files existAcross sessions, until something deletes it
Fails byDegrading as it fills; costing a resend every stepReturning the wrong chunkRemembering things that were never true

In the workshop stack these are three separate systems: the prompt, QMD over the vault, and Hindsight over conversations.

03Taxonomy

Four kinds of memory, plus the one that matters most

The standard split comes from CoALA (Sumers et al., 2023), which gives language agents working, episodic, semantic and procedural memory.

Workingshort-termWhat it isThe scratchpad the model reasons over directly: this turn’s promptIn our stackThe ~18,500-token prompt Hermes rebuilds on every callBounded byContext window and your bill
Episodicwhat happenedWhat it isConcrete records: turns, tool calls, observations, with timestampsIn our stackstate.db, searchable with session_searchBounded byDisk. Effectively unlimited
SemanticfactsWhat it isDistilled statements about the world and the userIn our stackUSER.md and Hindsight’s world/experience factsBounded byCharacter limits, or a provider’s store
Proceduralhow toWhat it isRules and routines that govern behaviourIn our stackSkills, and AGENTS.md in the vaultBounded byWhat you review and commit
Observationsconsolidated beliefsWhat it isDeduplicated beliefs built on top of raw facts, with evidence and a proof countIn our stackWhat Hindsight injects by default, instead of raw factsWhy it mattersDenser per token, and it survives repetition without duplicating

Hindsight splits its store into four networks: world (objective facts), experience (the agent’s own history), opinion (judgments) and observation (entity summaries).

04The case for a store

A bigger context window doesn’t fix it

Long context degrades

Chroma’s Context Rot study tested 18 frontier models and found accuracy falling at every input-length increment. A single distractor hurts; four compound it. Models even did better on shuffled text than on logically ordered text. On LongMemEval there are large drops between a focused ~300-token prompt and the full ~113K-token version.

And you pay for it every step

An agent re-sends its whole prompt on every call. Our measured runs: ~18,500 tokens per call for a question, 222M prompt tokens in a typical month. Mem0 reports memory-augmented agents at ~2,000 tokens per turn versus ~50,000 for context stuffing over 100 turns.

Managing context is itself a lever

Anthropic reports +29% on an agentic-search eval from context editing alone, +39% with a file-based memory tool as well, and 84% fewer tokens across a 100-turn web-search workflow.

The trap“Just use a 1M-token model” makes a system that is slower, more expensive and less accurate than one that retrieves 5 relevant facts.
But noteMemory is not free either: naive injection of a 200-entry store costs ~4,600 tokens per call versus ~130 for a top-5 retrieval.
Files as memoryClaude Code’s CLAUDE.md hierarchy is the simplest version of this idea. It loads at launch, so imports don’t save context, and files past ~200 lines get followed less reliably.

07The landscape

Six ways to build the same thing

Every system answers two questions: what is the unit of memory, and who decides what gets written.

HindsightUnitTyped facts (world, experience, opinion) consolidated into observationsMechanismretain → extract + entity-resolve + graph-link → consolidate; recall runs vector, BM25, graph and temporal in parallel with no LLM; reflect adds oneRunsDocker or cloud
Mem0UnitExtracted facts with temporal metadataMechanismTwo phases, write and read, joined by graph entity-linking and a temporal layer recording when something happened and whether it still holdsRunsCloud, self-host or in-process
HonchoUnitA model of each person (“peer”)MechanismTheory-of-mind inference builds psychological profiles; you query them in natural language through a dialectic endpointRunsCloud or self-host
OpenVikingUnitFiles in a virtual filesystemMechanismMemories, resources and skills under one tree you can ls and find; each entry written at three depths, loaded only as deep as neededRunsSelf-host
cogneeUnitGraph nodes and edgesMechanismExtract, cognify, load: an LLM pulls entities and relations into a hybrid graph + vector store, validated against an ontologyRunsSelf-host
LettaUnitMemory blocks the agent edits itselfMechanismThe agent manages its own context blocks; consolidation moved to “sleep-time” compute, off the user-facing pathRunsCloud or self-host
Plain filesUnitMarkdown you can readMechanismA hierarchy of rules files loaded at launch; the agent edits them through ordinary file toolsRunsYour disk

09Failure modes

Memory fails in ways search doesn’t

A wrong search result is discarded at the end of the turn. A wrong memory is still there next month.

What our agent stored in one dayWhat was true
“All wikilinks resolve, no orphaned pages.”

13 of 23 links were broken. The agent’s failed lint was retained as an experience, and would have been recalled as fact.

“RAG Precision Enhancement”, “Reranking Models”…

Entities invented from a web-search answer, stored as if they were notes in the vault.

“The user explicitly allowed writing to …/hermes-demo-scratch.md.”

A one-off test permission becoming standing consent. Now deleted automatically by the demo script.

And the researched ones

Poisoning. A systematic study of six attack classes measured 34.25% average attack success against a conservative-write agent and 66.67% against an aggressive one, peaking at 85.17% for compaction poisoning. Prompt-injection defenses covered it only partly.

It has happened. SpAIware planted persistent exfiltration instructions in ChatGPT’s long-term memory through a malicious page, so later conversations kept leaking.

Privacy. Memory holding personal data is personal data. Deleting from an index removes retrievability, which is not the same as erasure, and vector stores can’t easily prove it.

The patternAttack success scales with how eagerly the agent writes and reads memory, and injection can be separated from damage by weeks. An agent that stores everything is a bigger target than one that stores what its mission says.
10Practice

Treat it like a database you own

Scope the writing

Say what not to keep

  • A retain mission steers extraction. Misconfigured missions are the biggest cause of junk memories.
  • Ours forbids credentials, tokens and connection strings.
  • Turn on write approval while you’re still tuning.

Isolate and expire

One bank per context

  • A memory bank is the unit of separation between users, agents and projects.
  • Tag a TTL by category at write time: permanent for stable facts, days for transient ones.
  • Combine expiry, relevance decay, and supersession on write so contradictions don’t pile up.

Review and prune

Look at it after a bad run

  • Browse the store’s UI; ours runs at localhost:9999.
  • Delete a bad session by its document id, which removes the memories derived from it.
  • Clear wrong lines out of the hot files by hand: they’re just Markdown.
curl -X DELETE http://127.0.0.1:8888/v1/default/banks/<bank>/documents/<session_id> → Document and 2 associated memory units deleted successfully
11Does it help?

Test it the cheap way: turn it off

Nobody can tell you whether memory improves your agent. An ablation on your own questions can.

A one-afternoon eval

  1. Write 20 questions you actually ask, including 5 that depend on something you said in an earlier session.
  2. Run them with the provider on, then with hermes memory off.
  3. Score four axes: recall, freshness, contradiction handling, forgetting.
  4. Record tokens and latency per answer as well as accuracy, since all three move together.

Typical workload: 4.5 h/day × 30 days, ~2,600 tasks. Extraction adds roughly 18% to a cloud model’s bill if you leave it on the main model.

If the ablation shows no difference, you don’t have a memory problem. You have a search problem.
